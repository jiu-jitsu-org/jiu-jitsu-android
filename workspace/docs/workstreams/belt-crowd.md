# Belt Crowd Android 구현

몸통·눈 PNG와 장면용 SVG를 이관하고 Android의 시작, 독립 로그인, 자동 로그인 인사에 연결했다. 좌표, 레이어 순서, 모션 타임라인과 요일 인사 문구는 [전달받은 명세](../../../belt_crowd.md)를 기준으로 한다. 장면 동작과 폴더블 실기기 검증은 대기 중이다.

## 리소스

- 몸통 5개와 눈 5개는 [`:core:ui`의 `drawable-nodpi`](../../core/ui/src/main/res/drawable-nodpi)에 있다. `belt_body_*`, `belt_eyes_*` 이름을 사용한다. 원본 바이트와 픽셀 크기가 일치하므로 투명 여백을 포함한 원본 좌표를 그대로 쓸 수 있다.
- 패턴, 로고, 태그라인의 원본 SVG는 [공용 아트워크](../../core/ui/artwork/belt_crowd)에 보관했다. [`drawable`](../../core/ui/src/main/res/drawable)의 `belt_crowd_pattern`, `belt_crowd_logo`, `belt_crowd_tagline` 벡터는 각각 `555 × 788`, `271 × 98`, `265 × 24` 뷰포트와 원본 경로를 사용한다. 태그라인 원본의 그룹 투명도 `0.9`는 Compose `Image`의 `alpha`로 이미지 전체에 한 번 적용한다.
- 요일 말풍선에는 [공용 Pretendard SemiBold](../../core/ui/src/main/res/font/pretendard_semibold.otf)를 사용한다.

## 구현과 진입점

| 위치 | 현재 동작 | 구현 방향 |
| --- | --- | --- |
| [`:core:ui`](../../core/ui/src/main/java/kr/bjj_oss/ui/belt) | 공용 띠 장면과 별도의 프로필용 띠 아이콘을 제공한다. | 배치와 포즈를 계산하고 Compose Canvas에서 몸통·눈과 점 말풍선을 그린다. 글 말풍선은 Compose `Text`를 사용한다. 장면 진행은 화면 생명주기에 맞춰 갱신한다. |
| [`LoginScreen`](../../feature/login/src/main/java/kr/bjj_oss/login/screen/LoginScreen.kt) | 스크롤 가능한 로그인 버튼 영역과 가입 약관 시트를 제공한다. | 장식 레이어를 네이티브 버튼 영역과 분리했다. 명세의 `260dp + 하단 여백`은 기준 화면 검산에 사용한다. 실제 가림 기준선은 버튼·인셋·글자 크기를 반영한 시트의 최종 높이에서 구한다. 기존 테스트용 카카오 버튼까지 포함하면 현재 버튼 영역은 이 기준 높이를 넘는다. |
| [`AppNavHost`](../../app/src/main/java/kr/bjj_oss/ui/navigation/AppNavHost.kt)와 [`MainActivity`](../../app/src/main/java/kr/bjj_oss/MainActivity.kt) | 앱 시작 시 자동 로그인에 성공하면 현지 요일의 인사를 표시한다. 건너뛰기와 신규 가입 완료는 홈으로 이어진다. | 실제 홈을 먼저 구성한 뒤 홈의 위치와 상단 모서리를 애니메이션으로 바꿔 인사 장면을 덮는다. 모션 감소가 켜져 있으면 바로 홈을 표시한다. |
| [`WebLoginFlow`](../../app/src/main/java/kr/bjj_oss/ui/navigation/WebLoginFlow.kt) | 같은 `LoginScreen`을 웹 컨테이너 안에 표시하고 결과를 원래 WebView에 돌려준다. | 첫 구현은 독립 로그인 장면에 적용한다. 웹 로그인에 확대할 때는 상위 패딩을 포함한 실제 제약과 성공·건너뛰기·뒤로가기 콜백을 따로 검증한다. |

## 폴더블과 가변 창 대응 조건

`:app`에서 AndroidX WindowManager의 `FoldingFeature`로 분리 또는 가림이 있는 힌지를 관찰한다. 공용 장면은 창 좌표를 로컬 좌표로 변환하고 상위 레이아웃 제약과 런타임 인셋을 반영해 안전 영역을 정한다. 명세의 `393dp`는 원본 좌표계이며, 확대·축소에는 선택한 영역의 가용 폭과 높이를 모두 사용한다. [Android 창 크기 클래스](https://developer.android.com/develop/ui/compose/layouts/adaptive/use-window-size-classes), [FoldingFeature](https://developer.android.com/reference/androidx/window/layout/FoldingFeature)

| 환경 | 배치 조건 |
| --- | --- |
| 접힌 커버 화면·좁은 분할 창 | 단일 열을 사용한다. 로그인 시트가 가용 높이를 넘으면 스크롤로 모든 로그인 버튼과 건너뛰기에 접근할 수 있어야 한다. 공간이 부족하면 캐릭터·브랜딩 장식을 먼저 축소하거나 생략한다. |
| 펼친 내부 화면·태블릿·넓은 창 | 배경은 창 전체를 채우고, 캐릭터와 로그인 시트는 가로 중앙에 폭을 제한한다. 버튼 영역의 기존 `560dp` 상한을 유지한다. 가로 모드처럼 폭에 비해 높이가 작을 때도 안전 영역 높이 안에 장식을 배치한다. |
| 세로 힌지가 영역을 나누는 책 자세 | 로그인 시트와 캐릭터·말풍선을 하나의 안전 영역 안에 둔다. 콘텐츠를 배치할 영역은 가용 크기로 정하고, 같은 크기라면 레이아웃 시작 쪽을 선택한다. |
| 가로 힌지가 영역을 나누는 테이블톱 자세 | 위쪽 영역은 캐릭터·브랜딩·말풍선에, 아래쪽 영역은 로그인 조작부에 사용한다. 조작부는 아래쪽 영역에서 스크롤할 수 있어야 한다. 인사 장면은 위쪽 안전 영역의 하단을 캐릭터 기준선으로 쓴다. |

- 힌지가 창을 나누거나 화면 일부를 가리면 버튼·로고·말풍선과 캐릭터가 그 영역을 가로지르지 않도록 배치한다. 컷아웃과 시스템 바 인셋은 화면에서 한 번 적용한다. 접힘 정보가 없는 창은 동일한 제약 기반 단일 영역 배치를 사용한다.
- 접기·펼치기·회전·분할 화면 크기 변경 중에는 시트 가림 기준선과 말풍선 앵커를 새 영역으로 다시 계산한다. 같은 화면 항목에서 진행 중인 인트로·인사, 화자와 문구, 로그인·약관 상태를 이어간다. Activity 재생성도 검증하고, 이미 끝난 인트로·인사 또는 홈 이동 이벤트가 다시 실행되지 않도록 한다.

## 구현 순서와 검증 기준

1. 검은 띠부터 정적으로 그린다. `393 × 852`, 하단 인셋 `34` 기준으로 시트 상단 `562`, 몸통 프레임 `(135.55, 250.00, 110.66, 478.53)`, 머리 앵커 `(195.81, 250.05)`, 눈 크기 `107.52 × 38.44`를 검산했다. 이후 다섯 명의 순서, 파란 띠의 몸통 반전과 개별 눈 반전을 좌표 테스트에 추가한다.
2. 등장·숨쉬기·깜빡임·발화 포즈를 경과 시간을 입력받는 순수 함수로 계산한다. 프레임 값은 장식 레이어의 그리기 단계에서 읽는다. 로그인 점 말풍선의 충돌, 최대 두 개 동시 표시, 인트로를 마친 화면의 복귀 상태와 이탈 시 반복 작업 취소를 검증한다.
3. 앱 시작 인사에서 현지 요일별 화자와 문구를 한 번 고른다. 인사 말풍선과 홈 덮기 종료를 검증한다. 모션 감소 상태에서는 로그인은 정적 장면을 표시하고 인사는 건너뛴다.
4. [Adaptive Compose UI](../development/adaptive-ui.md)의 320·360·600dp, 가로 모드, 글자 크기와 시스템 인셋 사례에서 버튼 접근성, 장면 가림과 말풍선 위치를 확인한다. 시간 경계는 단위 테스트, 화면 진입과 복귀는 비스크린샷 상호작용 검사로 검증한다.
5. 폴더블 에뮬레이터 또는 실기기에서 커버 화면 ↔ 내부 화면, 책 자세 ↔ 테이블톱 자세, 가로 회전과 분할 화면 크기 조정을 확인한다. 로그인 인트로·약관 표시·인사 진행 중 각각 전환해 시트와 말풍선의 재배치, 버튼 접근성, 약관 선택 유지, 인사 재시작 및 홈 전환 중복 여부를 검증한다. 세로·가로 힌지와 좁고 낮은 창은 좌표 단위 테스트에도 포함한다.

리소스 준비 단계에서 PNG 10개와 SVG 원본 3개의 SHA-256 일치, PNG 크기와 RGBA 포맷, 신규 Android 리소스 13개의 AAPT2 컴파일과 `:core:ui:packageDebugResources` 통과를 확인했다. 구현 변경의 빌드·테스트와 장면 동작 검증은 사용자 확인 단계에 남겨 둔다.
